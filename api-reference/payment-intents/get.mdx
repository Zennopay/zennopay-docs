---
title: "Get payment intent"
api: "GET /v1/payment_intents/{intent_id}"
description: "Fetch the current state of a payment intent."
---

Authenticate with either partner HMAC or a session bearer token bound to this
intent. The bearer-token projection contains only SDK-safe fields; the HMAC
projection contains the complete partner record. Bearer status reads verify but
do not consume the token `jti`.

## Bearer/SDK response

```json
{
  "id": "0198f31a-7c2b-7d91-9fa2-112233445566",
  "reconciliation_ref": "zpr_...",
  "status": "authorized",
  "amount_usd_cents": 345,
  "corridor": "vn_vietqr",
  "created_at": "2026-09-02T12:00:00.000Z",
  "updated_at": "2026-09-02T12:00:03.000Z"
}
```

## Payment lifecycle

| Status | Meaning | Next action |
|---|---|---|
| `created` | Intent exists; payment is not yet confirmed. | Present PaymentSheet. |
| `authorized` | Wallet execution or merchant delivery is in progress or under recovery. | Continue tracking the existing intent. |
| `captured` | Merchant delivery succeeded. | Reconcile the completed payment. |
| `failed` | Payment reached a final failure. | Reconcile the failure. |
| `expired` | Intent expired without completion. | End this checkout attempt. |
| `refunded` | Payment was refunded. | Reconcile the returned funds. |
| `reversed` | Delivery was reversed. | Reconcile the reversal. |

`created` and `authorized` are non-terminal. A captured payment may later be
refunded or reversed, so continue processing subsequent events. An SDK
`pending` result is a client outcome; the stored intent keeps its API status.

## Partner/HMAC response

The HMAC response adds partner identifiers, QR/merchant and quote state,
execution references, confirm state, timestamps, and other reconciliation
fields. Every BIGINT-denominated local amount is serialized as a decimal int64
string, including:

- `provider_local_amount_minor_units`
- `qr_amount_minor_units`
- `quote_local_amount_minor_units`

Fields with no value are `null`.

Cross-partner access is rejected. Use [Reconciliation](/concepts/settlement)
for recovery guidance and [QR Payments webhooks](/api-reference/webhooks) for
signed status events.
